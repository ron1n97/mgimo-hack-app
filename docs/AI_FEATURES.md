# In-product ИИ — имба (ядро, не бонус)

**Решение владельца 2026-11-04:** ИИ-фичи в продукте обязательны.  
Критерии: в первую очередь **#2** (нейротехнологии) + **#1** (смелая идея деканата) + **#4** (приятный помощник, не мусор).

## Принцип

ИИ действует **на состоянии кабинета** (оценки, расписание, заявки), а не отвечает энциклопедией вуза.  
Generic FAQ-чат без контекста = **запрещён** как единственная ИИ-фича (`SCOPE.md` / `CLAUDE.md`).

## Y — consigned AI surface

| ID | Фича | Боль | UX |
|----|------|------|-----|
| AI1 | **Черновик заявки/справки** из профиля+контекста («справка об обучении», академический риск) | S4 D2 | Кнопка в заявках → превью текста → студент правит → submit |
| AI2 | **«Что делать дальше»** по успеваемости (3 next actions, без юридических гарантий) | S6 | Блок на экране успеваемости |
| AI3 | **Разбор переноса/дедлайна** простым языком из уведомления | S5 S8 | CTA «объясни» в ленте |
| AI4 | **In-app ассистент** (чат + widget DSL → карточки-ссылки) | S4–S8, staff | FAB → sheet; `POST /ai/chat`; ADR 0007 |

Сервер: ключи LLM только в env; в браузер не светятся. Для демо допустим mock/fallback текст, если ключа нет — но UI ИИ **виден**.

### AI4 — widget DSL (кратко)

Канон: `{{widget:KIND|id=…|title=…}}`; шорткаты `[[today]]`, `[[lesson:id=…]]`.  
Роли: student / staff / admin (+ teacher-compatible prompt). Read-only tools; write/HITL остаётся в Telegram-боте.

## N — не делаем под видом ИИ

- Боковой ChatGPT «спроси что угодно про МГИМО»
- Автоотправка заявок без подтверждения студента
- Оценка «вас отчислят» как факт
- Подключение к боевым API вуза

## Связь с критерием 2 (процесс)

В PDF: промпты AI1–AI3, фейлы галлюцинаций, как проверяли, субагенты/Cursor.  
In-product ИИ **не заменяет** forensic PDF процесса сборки — нужны оба слоя.
