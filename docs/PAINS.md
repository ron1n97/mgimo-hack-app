# Боли стейкхолдеров — продвигать везде

**Правило:** каждая боль либо (a) закрыта экраном/сценарием, либо (b) честно в PDF как «следующий шаг».  
Не прятать. Продвигать в онбординге, пустых состояниях, демо, PDF («какую проблему решает»).

Легенда: **F** = факт с источником · **H** = гипотеза (нужен опрос T1) · **B** = из брифа партнёра.

---

## Студент

| ID | Боль | Tag | Как продвигаем в продукте |
|----|------|-----|---------------------------|
| S1 | Учёба размазана: расписание / оценки / справки / объявления в разных местах | B | Home = единый «сегодня» |
| S2 | С телефона особенно неудобно | B | Mobile-first, нижняя навигация |
| S3 | Трудно найти нужное / нужны инструкции | B | ≤2–3 тапа до ядра; без мануала |
| S4 | Непрозрачный статус справки/заявления («подал и тишина») | H | Status theater + уведомления |
| S5 | Переносы/изменения пар замечаешь поздно | H (+F каналы: RUZ/app/бот отдельно) | Бейджи переносов в расписании + push-лента |
| S6 | Непонятно «как у меня дела» до сессии | H | Экран успеваемости с ризиком/зелёной зоной |
| S7 | Официальный ЛК/app глючит, сессии, расписание подгрупп | H/F* | Дисклеймер концепта; UX-контраст «как могло бы быть» |
| S8 | Дедлайны и новости деканата тонут в чатах/почте | B/H | Единая лента уведомлений |

\*F частичные: публичные отзывы на приложение «МГИМО» (агрегаторы) — UX/auth/schedule friction; не репрезентативная выборка. Живые цитаты МГИМО — TODO T1.
