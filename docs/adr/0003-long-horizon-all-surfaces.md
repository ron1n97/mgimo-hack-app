# 0003. Долгий горизонт · все поверхности · Z Code

## Статус
Принято — 2026-11-08 (owner, устно)

## Контекст
Owner: пофиг на дедлайн как ограничитель амбиции; нужны сайт + мобилка + телега + «всё» (в т.ч. контуры сотрудников); платит сам; LLM через Z Code в режиме совместимости с OpenRouter; к сдаче конкурса всё равно целимся успеть — полнота = преимущество.

## Решение
1. Профиль продукта: **long-horizon platform**, не checklist-floor. Дедлайн 22.11 = milestone сдачи, не потолок scope.
2. Поверхности v1-платформы: **Web (PWA) + Telegram bot + Mobile (кроссплатформа, один код — Expo/React Native или эквивалент)**.
3. Контуры: студент **и** сотрудник/деканат (не откладывать «на потом» как N).
4. Infra: Docker multi-service, Postgres, Redis, workers, CI/CD; без SQLite как SoT; без ручного one-off деплоя как нормы.
5. LLM: клиент **OpenAI-compatible / OpenRouter-style** → base URL + API key провайдера **Z Code** (секреты только в env / secret store, не в git/чате).
6. Расписание МГИМО: sync групп через публичный RUZ API.
7. Конкурсные ограничения брифа **сохраняются** в сдаваемой сборке: fake PII, дисклеймер, без лого вуза, изоляция, RU-доступ.

## Последствия
- Больше работы; нужна нарезка релизов (CHANGELOG) и параллельные агенты.
- Mobile store publish может отставать от web/bot — но код мобилки в репо с дня 1.
- Риск не успеть «идеально всё» к 22.11: сдаём working cut + продолжаем; не режем поверхности заранее без ADR.
