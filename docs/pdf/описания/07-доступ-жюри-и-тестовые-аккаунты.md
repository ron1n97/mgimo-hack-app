# 7. Доступ для жюри из РФ · тестовые аккаунты с разными данными

**Для кого этот текст.** Два правила сдачи, без которых прототип «не существует» для эксперта: **открыть без VPN** и **войти под разными ролями**, чтобы увидеть разделённые данные.

| Правило | Суть |
|---------|------|
| **A. Доступность** | Прототип открывается из России без VPN и живёт до объявления итогов — **28 ноября**; хостинг — любой |
| **B. Тестовые аккаунты** | ≥2 студента с **разными** данными (видно разделение) + аккаунт сотрудника, если есть кабинет staff |

---

## A. Доступность для жюри (РФ · без VPN · до 28.11)

### Как закрыто

| Требование | Деканат+ |
|------------|----------|
| Из России без VPN | Live на **российском VPS**, HTTPS через Caddy + Let’s Encrypt |
| Работает до итогов (28.11) | Compose `restart: unless-stopped`, CI deploy на `main`, owner держит стенд (канон R1) |
| Хостинг — любой | Не «только Vercel»: свой Docker-стек на VPS; зеркало/не sole зарубежный serverless — в `CLAUDE.md` |

**Публичные URL**

| Поверхность | Адрес |
|-------------|--------|
| Web / PWA | https://dekanat.177.177.212.34.sslip.io |
| API | https://api.dekanat.177.177.212.34.sslip.io |

Домен `*.sslip.io` по публичному IP — без регистрации DNS у жюри. Порты хоста только **80/443**; web и api за reverse-proxy Caddy (`docs/DEPLOY.md`).

Выкладка: GitHub Actions → образы GHCR → SSH на `/opt/mgimo-hack-app` → `docker-compose.prod.yml`. Секреты в GitHub Secrets / `.env` на сервере, не в репозитории.

Канон проекта: *URL из РФ без VPN до 28.11.2026*; owner подтверждает **R1** («live можно жюри»), не sole Vercel/Railway.

### Что открыть жюри за 10 секунд

1. С телефона или ПК в РФ — web URL выше (без VPN).  
2. Увидеть дисклеймер «Неофициальный цифровой кабинет…».  
3. Кнопки демо-входа на `/` (если `DEMO_QUICK_LOGIN=true` на стенде).

## B. Тестовые аккаунты (≥2 студента + сотрудник)

### Зачем два студента

Требование: *разные данные*, чтобы было видно **разделение**.  
У нас это не формальность: разные группы/подгруппы RUZ, разный профиль успеваемости (долги у Рисковой vs спокойный сценарий у Бориса), изоляция заявок (см. описание 06 про IDOR).

Скрин-доказательство: `14-студент-спокойный-сегодня-телефон.png` рядом с кадром Рисковой.

### Быстрый вход (рекомендуется жюри)

На главной `/` — кнопки persona. Клиент шлёт `POST /auth/demo-login` с `personaId`; **пароли не лежат в JS** (`docs/DEMO.md`).

| Кнопка / personaId | Почта | Что увидит жюри |
|--------------------|-------|-----------------|
| **Студент Рискова** · `student-anna` | `anna.risk@demo.local` | `2МЭО-01`, язык `10169` (01-нем/англ), долги / «риск»-сценарий, заявки Анны |
| **Студент Спокойный** · `student-boris` | `boris.ok@demo.local` | `2МЭО-02`, язык `10194` (05-испан/англ), **другие** данные кабинета |
| **Сотрудник Соколова** · `staff-elena` | `staff@demo.local` | Кабинет сотрудника: очередь заявок, staff-экраны |

Дополнительно (не обязательно для минимума, но есть в seed):

| personaId | Кто |
|-----------|-----|
| `student-kirill` | ещё один студент МЭО (`4МЭО-01`) |
| `admin-platform` | админ платформы |

### Обычный вход по почте

Пароль для всех демо-учёток: **`Demo123!`**  
(хранится как bcrypt-хеш в БД, не plaintext.)

### Как показать жюри «данные разделены» за минуту

1. Войти как **Рискова** → «Сегодня» / «Учёба» / «Заявки» — запомнить долги и список заявок.  
2. Выйти → войти как **Спокойный** → другие ФИО, другая группа, **нет** чужих заявок/долгов Анны.  
3. Войти как **Соколова** → `/staff/requests` (и при желании подбор расписания) — кабинет сотрудника.

Так закрыты сразу два требования: тестовые аккаунты + наглядная изоляция данных.

### Включение на прод-стенде

В `.env` VPS: `DEMO_QUICK_LOGIN=true` → перезапуск API.  
Без флага в production demo-login выключен (`403`) — на стенде сдачи флаг включён намеренно для жюри.

Полная шпаргалка: `docs/DEMO.md`.
