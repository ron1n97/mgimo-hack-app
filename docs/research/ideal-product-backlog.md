## 2. Домены фич (таксономия идеала)

### A. Учёба
Расписание (день/неделя/сессия) · переносы · свободные аудитории · зачётка · «как дела» / риск · материалы (позже) · элективы (фаза 2)

### B. Деканат / операции
Каталог справок и заявлений · статус + SLA · таймлайн · вложения · сотрудник: очередь, смена статуса, комментарий · шаблоны

### C. Коммуникации
Единая лента · push web/mobile · Telegram-пуши · таргет объявлений · тихие часы

### D. ИИ (наше пустое поле рынка)
AI1 черновик заявки · AI2 next actions по учёбе · AI3 объяснить перенос/дедлайн · позже: разбор «почему риск», черновик обращения к преподу (с подтверждением человека)

### E. Деньги / быт (фаза 2+)
Стипендия/договоры (seed или интеграция) · карта корпусов · запись к врачу/секции (как у Life/ITMO)

### F. Карьера / wellbeing (фаза 2+)
Портфолио · вакансии/практики · хаб помощи (куда идти)

### G. Платформа
Auth регистрация/логин · роли student/staff/admin · PWA + Mobile + Bot · Postgres · Docker · audit log · RU-host

## 4. Принципы идеала (чтобы не расползтись)

1. **Один Today** — если фича не попадает на Today или в заявку/расписание/ИИ — подозревай мусор.  
2. **ИИ только с контекстом кабинета** — иначе мы как худший FAQ-бот.  
3. **Статус заявки священен** — как у ВШЭ, не «письмо в никуда».  
4. **Расписание правдивое** — RUZ sync + fallback; пуш изменений обязателен.  
5. **Сотрудник first-class** — иначе это не деканат, а студенческий виджет.  
6. **Три клиента, один API** — web / mobile / bot не живут своей жизнью.  
7. **Конкурсный режим** — fake data + дисклеймер; прод-интеграции позже.
