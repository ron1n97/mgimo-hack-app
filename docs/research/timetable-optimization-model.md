## 1. Цель и предметная область

Построить **формальную задачу назначения** учебных занятий (активностей) на кортеж *(таймслот, аудитория, преподаватель)* для академических единиц МГИМО-подобного вуза так, чтобы:

1. закрыть учебный план (покрытие требуемых часов / сессий);
2. учесть жёсткие ограничения ресурсов (столкновения, вместимость, оснащение, доступность, ставка);
3. оптимизировать мягкие критерии (окна преподавателей и групп, баланс нагрузки относительно ставки, предпочтение кафедры дисциплины, стыки корпусов).

Документ переводит вербальное описание домена в множества, индексы, параметры, переменные, жёсткие ограничения и скаляризованный линейный критерий с настраиваемыми весами $\lambda_k$.

## 2. Домен RUZ / МГИМО (факты модели v1)

### 2.1. Иерархия и три механизма построения $C$ и $K_{c,c'}$

Коллега (МЭО): курс → обычно **2 потока** (чаще для лекций) → поток делится на **3–4 академические группы** (профильные семинары) → академическая группа делится на **2–4 языковые группы** (языковые семинары). Физкультура в разметке РУЗ **неясна** (коллега не помнит обозначение) — в v1 не выделяем отдельный kind, пока не появится стабильный признак в данных.

**Атомы назначения** $C$ — тонкие когорты. На практике занятие в РУЗ попадает в $C$ одним из трёх механизмов (оценки по разбору сетки, не нормативные доли плана):

| Механизм | Доля занятий (ориентир) | Как строить когортy / конфликт |
|----------|-------------------------|--------------------------------|
| **Языковая подгруппа-профиль** | ≈61% | Атом $c$ = языковая подгруппа своей академической группы; академическая группа = объединение своих языковых подгрупп |
| **Поток** | ≈15% | Парсинг имени `Поток_…(подгруппы…)` / лекционные потоки из групп; когорта-поток конфликтует со всеми входящими атомами |
| **Целая академическая группа** | ≈20% | Назначение на $g \in G$ целиком (все языковые атомы группы заняты) |

**Ключевое допущение v1:** один студент ∈ **ровно одной** языковой подгруппе своей академической группы. Тогда матрица конфликтов $K_{c,c'}$ строится **без списков студентов**:

- два языковых атома одной академической группы **не** конфликтуют друг с другом (разные студенты);
- атом конфликтует с потоком / академической группой / МИЭП-объединением, если входит в их состав;
- два потока конфликтуют, если пересекаются по атомам.

МИЭП:

- **МЭО-МИЭП / МО-МИЭП** на лекциях идут **вместе** с соответствующими МЭО / МО (общий лекционный пул);
- с **3 курса** у МЭО ≈ **8 специализаций**: общие лекции/семинары курса + спец. семинары специализации (атомы специализации конфликтуют с общими блоками того же курса и между собой при пересечении состава).

| ID | Факт / допущение | Следствие для модели |
|----|------------------|----------------------|
| A1 | Множество тонких когорт $C$ — единицы назначения | Решаем не «на N групп», а на элементы $C$ (+ агрегаты поток/группа как суперкогорты с теми же $K$) |
| A2 | Вложенность: поток ⊃ академическая группа ⊃ языковая подгруппа; пересечений «студент в двух языковых» нет | $K$ из состава, без ортогонального разреза |
| A3 | Учебный план привязан к паре *(дисциплина, когорта $c \in C$)* и типу занятия $\tau$ | Часы задаются на уровне $(c,d,\tau)$ |
| A4 | Конфликт по времени = ребро в $K$ (или self на $c$) | Жёсткий no-clash на когортах |
| A5 | Численность $h_c$ известна и постоянна на горизонте | Сравнение с вместимостью |
| A6 | Горизонт — дискретный грид слотов с **минутной** геометрией (см. §2.4) | Конфликты $p$ по пересечению интервалов, не по «номеру пары» |
| A7 | Одна activity instance занимает один слот своей сетки; сдвоенные = две связанные активности | Упрощение v1 |
| A8 | У занятия в РУЗ обычно **один** преподаватель (`listOfLecturers` ≤ 1); два препода = **linked duplicate rows**, не расширение $x$ | Бинарное назначение; linked $a,a'$ делят слот/аудиторию по правилу препроцессора |
| A9 | Требования к оснащению — эвристики по виду×дисциплине + флаги аудиторий | Сужение домена $(a,r)$ |

### 2.2. Типы занятий $\mathcal{T}$

В сетке РУЗ реально встречаются:

- семинар, лекция;
- экзамен / контрольная / консультация / зачёт (и близкие контрольные формы);
- ≈324 записи «без вида» ≈ мероприятия / брони → **не** оптимизируем как учебные $a$, а фиксируем блокировки $\mathrm{Avail}^R_{r,t}=0$ (и при необходимости $\mathrm{Avail}^P$, $\mathrm{Avail}^C$).

Отдельных kind «язык» / «лабораторная» в справочнике вида **нет**: язык идёт как **семинар**; тип для требований оборудования выводить из пары **вид × дисциплина** (и эвристик аудиторий). Физкультура — uncertain (см. выше).

Коллега: «в расписании по сути лекции и семинары».

### 2.3. Аудитории и корпуса

- Справочник: порядка **18 типов** / флагов оснащения (расширяемый вектор $\phi_{r,f}$).
- Эвристики назначения: язык / лекция / семинар / IT / физ-ра → допустимые типы комнат.
- Исключить из $R$ ~**85 служебных «кабинетов»** (не учебные аудитории).
- **Виртуальный корпус** (~535 занятий/нед в разборе): аудитория **не нужна** — для таких $a$ домен $r$ = фиктивная «online/virtual» с $\mathrm{cap}=\infty$ и без конфликта с физическими $r$ (или отдельный пул без H3 между virtual и physical).

Здания $B$: кампус (Вернадского и др.) и **ДА** (отдельная площадка) — см. S6 / H10.

### 2.4. Грид таймслотов

- **8 пар** × **80 мин** (академический час = **40 мин**, duration пары = 2 ак. часа).
- Две сетки **по факультету**: **МО** vs **МЭО** (у МЭО длинный обед на 3-й паре — сдвиг последующих слотов).
- Конфликты преподавателя (и любых ресурсов, живущих в обеих сетках) считаются по **пересечению минут**, не по совпадению номера пары: ≈**14%** teacher-дней встречаются в обеих сетках.

Параметры геометрии: для каждого $t$ заданы $\mathrm{start}(t),\mathrm{end}(t)$ (минуты от начала недели или абсолютное время шаблона), $\mathrm{day}(t)$, $\mathrm{facultyGrid}(t)\in\{\mathrm{MO},\mathrm{MEO}\}$, $\mathrm{ord}(t)$.

### 2.5. Стыки корпусов (S6 / H10)

- Внутри **Вернадского** (и сопоставимого кампуса): смена корпуса в один день — **мягкий** штраф S6 (в разборе ≈21–24% стыков).
- Стык **ДА ↔ кампус** в один день у той же когорты / преподавателя — **жёсткий запрет** (H10).

### 2.6. Преподаватели, ставка, Wish, кафедральность

- `listOfLecturers` длины ≤ 1 в типовой записи; «обычно один преподаватель закреплён» (коллега).
- Два преподавателя на одну «логическую» пару → две строки РУЗ / linked activities, **не** multi-index в $x$.
- $W_p$ — бюджет в **академических часах / семестр** только **аудиторной** нагрузки (подготовка/консультации вне аудитории в $W_p$ v1 не входят, пока заказчик не расширит).
- $\mathrm{Wish}_{p,t}$ **из РУЗ API нет** → почасовики: жёсткая $\mathrm{Avail}^P$; штат: soft Wish только после опроса кафедр (пока $P_{\mathrm{wish}}=0$ или выключен $\lambda_{\mathrm{wish}}$).
- $P_{\mathrm{dept}}$: «своя» кафедра = **кафедра дисциплины** (через lecturer→кафедра / справочник дисциплины), **не** деканатская кафедра группы.

### 2.7. Качество исторических данных

В исторической сетке ~**80 пересечений / неделю** (в т.ч. аудитория `!Не определена`) — **не** считать эталоном feasibility. Солвер обязан быть строже грязных данных РУЗ.

### 2.8. Поверхность RUZ API (входные данные)

Публичный хост `https://ruz.mgimo.ru` (см. также worker/`RUZ_BASE_URL`):

| Поверхность | Назначение для модели |
|-------------|----------------------|
| `GET /api/dictionary/*` | Справочники (группы, аудитории, дисциплины, …) → $G,C,R,D,\phi$ |
| `GET /api/search` | Поиск group/lecturer → идентификаторы |
| `GET /api/schedule/{…}` (в т.ч. `schedule/group/{id}`) | Факт сетки, брони → семена $A$, $\mathrm{Avail}^R$, диагностика конфликтов |

Продуктовый кабинет читает кэш/БД после sync ([ADR 0009](../adr/0009-schedule-source-of-truth.md)); эта модель описывает **будущий** sidecar оптимизации, не текущий MVP.

## 3. Множества и индексы

| Символ | Описание |

| $K \subseteq C \times C$ | Конфликтующие пары когорт |

- $\mathrm{acad}(c) \in G$; $\mathrm{stream}(c)$ — поток при наличии;

## 5. Переменные решения

### 5.1. Назначение активности (CP-SAT-friendly)

$$
x_{a,t,r,p} \in \{0,1}
\quad — \quad
\text{активность } a \text{ в слоте } t \text{ в аудитории } r \text{ у преподавателя } p.
$$

**Обоснование:** булевы назначения + предперечисление сессий хорошо ложатся на OR-Tools CP-SAT; покрытие плана становится проверяемым (H1).

**Двухэтапная декомпозиция** (инженерный приём): Stage 1 — $p$ (и опционально день); Stage 2 — $(t,r)$ при фиксированном $p$.

Linked duplicates: для $(a,a')\in\mathrm{Linked}$ препроцессор либо фиксирует одного $p$ на каждую строку и общую пару $(t,r)$, либо вводит равенства на $y_{a,t}$ — без расширения размерности $x$ до multi-teacher.

### 5.2. Производные агрегаты

$$
y_{a,t} = \sum_{r,p} x_{a,t,r,p},\quad
u_{p,t} = \sum_{a,r} x_{a,t,r,p},\quad
v_{c,t} = \sum_{a:\,c(a)=c}\sum_{r,p} x_{a,t,r,p},\quad
z_{r,t} = \sum_{a,p} x_{a,t,r,p}.
$$

## 6. Жёсткие ограничения

### 6.1. Назначение ровно один раз

$$
\sum_{t,r,p} x_{a,t,r,p} = 1 \quad \forall a \in A.
\tag{H1}
$$

### 6.2. Нет столкновений преподавателя (по минутам)

$$
u_{p,t} + u_{p,t'} \le 1
\quad \forall p,\ \forall (t,t'):\ \mathrm{Overlap}_{t,t'}=1.
\tag{H2}
$$

(При слотах без пересечения сеток достаточно $\sum_{a,r} x_{a,t,r,p}\le 1$ на каждый $t$.)

### 6.3. Нет столкновений аудитории

$$
z_{r,t} \le 1 \quad \forall r:\ \neg\mathrm{isVirtual}_r,\ \forall t.
\tag{H3}
$$

### 6.4. Нет столкновений когорт

$$
v_{c,t} \le 1 \quad \forall c,t;
\qquad
v_{c,t}+v_{c',t}\le 1 \quad \forall (c,c')\in K,\ \forall t
\ \text{(и с }\mathrm{Overlap}\text{ при разных сетках, если когорта живёт в обеих).}
\tag{H4}
$$

### 6.5–6.8. Вместимость, оснащение, доступность, eligibility

Как в классической формулировке: (H5) $\mathrm{cap}_r \ge h_{c(a)}$; (H6) $\phi_{r,f}\ge req_{a,f}$; (H7) $\mathrm{Avail}^{C/P/R}$; (H8) $\mathrm{Elig}_{p,d(a),\tau(a)}$. Домен $x$ сужается препроцессором.

### 6.9. Верхняя граница ставки

$$
\sum_{a,t,r} \omega_a\, x_{a,t,r,p} \le W_p \quad \forall p.
\tag{H9}
$$

### 6.10. Запрет стыка ДА ↔ кампус

Пусть $B_{\mathrm{DA}}\subset B$, $B_{\mathrm{campus}}\subset B$. Если в один день $\delta$ у агента (преподаватель $p$ или когорта $c$) есть занятия в корпусах из обоих множеств — запрет. Линеаризация через индикаторы «день $\delta$ использует DA» / «использует campus».

$$
\mathrm{DA}_{p,\delta} + \mathrm{Campus}_{p,\delta} \le 1;\quad
\mathrm{DA}_{c,\delta} + \mathrm{Campus}_{c,\delta} \le 1.
\tag{H10}
$$

### 6.11. Покрытие: hard vs soft

**v1:** hard (H1). Soft-покрытие — только диагностический режим при `INFEASIBLE`.

## 7. Мягкие критерии и штрафы (веса $\lambda_k$)

Все штрафы неотрицательны и линейны (или линеаризуемы). Числовые веса не фиксируются.

Ориентир приоритета: (1) coverage если soft; (2) окна и нагрузка преподавателей, кафедральность дисциплины; (3) окна студентов; (4) мягкие стыки корпусов.

### 7.1–7.3. Coverage, окна преподавателей, баланс нагрузки

$P_{\mathrm{cov}}$ (S0, только soft-режим); $P_{\mathrm{gap\text{-}teach}}$ (S1) по first/last в **одной** сетке дня; $P_{\mathrm{load}}$ (S2) относительно $\alpha W_p$.

### 7.4. Предпочтение кафедры дисциплины

$$
P_{\mathrm{dept}} = \sum_{a,t,r,p} \mathbf{1}\bigl[ dept(p) \ne dept(d(a)) \bigr]\, x_{a,t,r,p}.
\tag{S3}
$$

### 7.5. Wish

Если задано после опроса: $P_{\mathrm{wish}}=\sum_{p,t}\mathrm{Wish}_{p,t}\,u_{p,t}$ (S4). Пока данных нет — $\lambda_{\mathrm{wish}}=0$.

### 7.6. Окна студентов

$P_{\mathrm{gap\text{-}stud}}$ (S5) аналогично S1 для $v_{c,t}$.

### 7.7. Стыки корпусов внутри кампуса

$$
P_{\mathrm{building}} = \sum_{\text{агент},\delta} \mathbf{1}[\ge 2\text{ разных корпуса кампуса в день }\delta].
\tag{S6}
$$

ДА↔кампус уже запрещён (H10). Опционально S7/S8 (стабильность аудиторий, сдвоенность).

## 8. Скаляризованный критерий

$$
\min_x \;
\lambda_{\mathrm{cov}} P_{\mathrm{cov}}
+ \lambda_{\mathrm{gap\text{-}teach}} P_{\mathrm{gap\text{-}teach}}
+ \lambda_{\mathrm{load}} P_{\mathrm{load}}
+ \lambda_{\mathrm{dept}} P_{\mathrm{dept}}
+ \lambda_{\mathrm{wish}} P_{\mathrm{wish}}
+ \lambda_{\mathrm{gap\text{-}stud}} P_{\mathrm{gap\text{-}stud}}
+ \lambda_{\mathrm{building}} P_{\mathrm{building}}
+ \sum_{k \in \mathcal{O}} \lambda_k P_k
\tag{OBJ}
$$

при (H1)–(H10) (и отключении $P_{\mathrm{cov}}$, если H1 жёсткий).

Ориентир: $\lambda_{\mathrm{cov}}\gg \lambda_{\mathrm{gap\text{-}teach}},\lambda_{\mathrm{load}},\lambda_{\mathrm{dept}} \gg \lambda_{\mathrm{gap\text{-}stud}},\lambda_{\mathrm{building}}$. Все $\lambda_k$ — внешние гиперпараметры.

## 9. Соответствие OR-Tools CP-SAT и препроцессинг

### 9.1. Sidecar

Решатель — **отдельный** worker/sidecar CP-SAT, не request-path API кабинета ([ADR 0010](../adr/0010-teacher-lesson-assignments.md), [ADR 0011](../adr/0011-timetable-optimization-model.md)).

### 9.2. Activity vs непрерывные часы

Рекомендуется pre-enumerated $A$; солвер только назначает $(t,r,p)$.

### 9.3. Сужение домена

Отбрасывать комбинации, нарушающие (H5)–(H8), virtual-правила и несовместимые сетки факультета когорты.

### 9.4. Масштаб

При больших $|A|$ — декомпозиция по дням / корпусам / кафедрам или Stage 1/2.
