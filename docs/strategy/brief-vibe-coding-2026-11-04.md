**Доступность для жюри:** до объявления итогов 28.11 (из РФ без VPN)

## Проблема (по брифу)

Учёба размазана: расписание / оценки / справки / объявления в разных местах; с телефона особенно больно.

## Задача

Работающий прототип ЛК студента («цифровой деканат будущего»): всё в одном месте, удобно, красиво, mobile-first, безопасно. Адаптация под свой вуз приветствуется; смелые идеи — плюс.

## Обязательное ядро

1. Вход и профиль (логин/пароль или иной способ; ФИО, факультет, направление, курс, группа)
2. Расписание (сегодня + неделя, аудитория, преподаватель, переносы)
3. Успеваемость (оценки/зачёты, сессия, «как у меня дела»)
4. Заявки и справки (заказ/подача + статус)
5. Уведомления (новости деканата, дедлайны, изменения)

## Требования к прототипу (сжато)

- Не Figma: живой URL, полный happy-path
- Стек любой, масштабируемый по смыслу
- Код через ИИ-ассистентов (список инструментов в PDF)
- Mobile ≥360px
- Только вымышленные ПДн; парсинг открытого расписания — ок
- Дисклеймер: концепт конкурса, не офиц. сервис
- Без логотипа вуза (свой «откликающийся» ок)
- Лицензии на стороннее
- Security: изоляция данных по студенту; пароли не plaintext; секреты не в коде/браузере
- ≥2 тестовых аккаунта студентов (+ сотрудник если есть)

## Сдача

Ссылка + аккаунты; репо/архив; PDF процесса (проблема, ИИ-стек, промпты, скрины, security простыми словами, ручные этапы); видео ≤5 мин — желательно.

## Критерии (до 10 каждый, среднее экспертов)

1. Проработанность идеи  
2. Масштаб использования нейротехнологий  
3. Имплементация  
4. Качество (дизайн/UX)
