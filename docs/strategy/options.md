# P2 Options — how to play (Вайб-кодинг)

**Рамка:** покупаем среднее 4×10, не «продукт на годы». IP при сдаче → Организатор ([rules §6](https://challenge.mgimo.ai/rules)).  
**Уточнение к брифу (факт):** PDF в сдаче = *описание процесса создания*; это не требование «ИИ парсит PDF внутри продукта». In-product AI — опциональный усилитель.

Kill-пороги из P1 действуют на все варианты.

---

## Option A — «Checklist Floor» (минимальная амбиция)

**Where to play / how to win:** закрыть обязательное ядро + 2 аккаунта + RU-хост + честный PDF процесса; взять «не провалиться», не «запомниться».

**Осознанные отказы:** bold UX, dual-skin СамГТУ, in-product LLM, парсинг RUZ, видео, дизайн-система.

| Кр. (hyp) | Идея | ИИ-процесс | Имплем. | Качество | avg |
|-----------|------|------------|---------|----------|-----|
| | 4–5 | 5–6 | 7–8 | 5–6 | **~5.5–6.3** |

**Steelman против:** вас съест толпа таких же CRUD; идея и качество упрутся в потолок.

**Факт vs hyp:** *Факт* — ядро обязательно. *Hyp* — «просто работает» даёт пол-шестёрки у экспертов-маркетологов.

**Kill варианта:** любой must-have сценарий ломается на телефоне; хост недоступен из РФ.

**14 дней:** D1–7 ядро → D8–10 хост+mobile → D11–12 PDF процесса → D13–14 багфикс/сдача.

---

## Option B — «Walk / Token» (закрыть или почти не вкладываться)

**Where to play / how to win:** не играть (или ≤3 дня token-upload ради сертификата). Победа = сохранённое время/фокус; приз не цель.

**Отказы:** ночи, Cursor-burn, дизайн, RUZ, моральный долг «дожать».

| Кр. (hyp) | avg **~2–4** или N/A |

**Steelman против:** 18 дней хватает на A/C; credential хакатона дешёвый; §6 IP страшен только если хотите продукт после.

**Факт vs hyp:** *Факт* — IP уходит при submit. *Hyp* — EV приза < cost 2×18 дней (зависит от альтернатив команды — **неизвестно**).

**Kill token-path:** scope creep >3 дней.

**14 дней:** D1 решение → (token) D2–4 сжатый A → стоп; иначе другие дела.

---

## Option C — «Process Theatre + RUZ» *(рекомендация агента)*

**Where to play / how to win:** один сквозной сценарий «студенческая жизнь → действие в деканате», живое расписание из [RUZ JSON](https://ruz.mgimo.ru/), forensic PDF/видео *как делали с ИИ* (кр.2), тонкое ядро без LMS-расползания. Дифференциация = связность + доказанный вайб-процесс, не число разделов.

**Отказы:** СамГТУ dual на v1; админка сотрудника (кроме login если успеете); generic AI-чат без контекста кабинета; «ещё модули»; пост-демо бэклог, который жалко отдавать по §6.

**Усилители (выбрать ≤2, не все):**
1. Два narrative seed-аккаунта (academic risk vs «всё ок») — одна UI, разный эмопуть.
2. In-product AI: черновик заявки/справки из контекста оценок+расписания (не FAQ-бот).
3. «Security demo»: переключение аккаунтов + попытка IDOR в UI для жюри.
4. Status theater заявок (таймлайн, понятный «почему ждём»).

| Кр. (hyp) | Идея 7–8 | ИИ 8–9 | Имплем. 7–8 | Кач. 6–7 | avg **~7.0–7.8** |

**Steelman против:** RUZ ляжет → нужен fallback seed; UI «дефолт AI» убьёт качество; PDF процесса тонкий = кр.2 всё равно мёртв; §6 отдаёт лучший клин.

**Факт vs hyp:** *Факт* — RUZ API жив 2026-11-04; PDF процесса в сдаче обязателен по брифу. *Hyp* — живой RUZ и narrative seeds читаются жюри как глубина.

**Kill → auto-downgrade to A:** RUZ нестабилен к D3 *и* нет красивого seed-fallback; к D10 mobile unreadability; появился второй «столп» фич.

**14 дней:**
- D1: lock сценария + seed personas + каркас PDF-лога
- D2–3: auth + 2 профиля + изоляция
- D4–5: schedule (RUZ + offline seed)
- D6: grades «как у меня дела»
- D7–8: заявки/справки + статус + уведомления
- D9: ≤1 усилитель (AI draft *или* security demo)
- D10: RU deploy + mobile pass
- D11–12: PDF процесса (промпты, фейлы, скрины) + видео≤5м
- D13: hostile QA по демо-скрипту
- D14: freeze / сдача капитаном

## Option D — «Dual-skin МГИМО↔СамГТУ» *(не default)*

**Where/how:** один код, переключатель вуза (брендинг/термины/расписание source). How to win = «масштабируемость» в кр.1/3.

**Отказы:** глубина сценария ради ширины.

| avg hyp **~5.5–6.5** — чаще хуже C из-за размаза |

**Steelman:** жюри видит недоделанные два скина; СамГТУ без JSON = больше ручной грязи.

**Kill:** любой скин ломает ядро; +2 дня сверх C-плана без готового C.

**Когда брать:** только если после C остаётся буфер *или* как 30-мин theme toggle без второй логики данных.
