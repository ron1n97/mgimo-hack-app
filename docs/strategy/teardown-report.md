# Teardown P1 — как выиграть Вайб-кодинг (не рынок деканата)

## Идея как понята (подтвердить владельцу)

Команда из 2 человек (капитан Максим, Роман) за ~18 дней до дедлайна собирает **жизнеспособный URL-прототип** ЛК студента «цифровой деканат будущего» в сеттинге **МГИМО** (опционально скин СамГТУ), с обязательным ядром из брифа, демонстрацией безопасности и **максимально документированным** процессом вайб-кодинга — чтобы максимизировать среднее по 4 критериям Регламента.

## Скоринг (переосмыслен под конкурс)

| Фактор | 0–10 | Обоснование |
|--------|------|-------------|

**Среднее ~6.6**, floor по «живым цитатам» = 3 → интерпретация **HOLD→ADVANCE к Options**, не VALIDATE рынка. Для конкурса: **ADVANCE к выбору ставки продукта**.

Мультипликативный floor методики startup здесь не KILL'ает: «рынок» = конкурс с фиксированной формулой баллов.

## Топ-риски победы

1. Фича-спам без сквозного сценария → низкая проработанность.  
2. Тонкий PDF («использовали Cursor») → убивает кр.2.  
3. Хост недоступен 23–27.11 → имплементация ≈0.  
4. Утечка данных между тестовыми аккаунтами.  
5. Похожесть на официальный ЛК + забытый дисклеймер/лого → дисквал по брифу.
